# AURA-native (декомпиляция HomeMusic 1.14.7)

Собираемый Gradle-проект, полученный декомпиляцией `HomeMusic.apk` 1.14.7
(<https://github.com/justman-1/HomeMusic-public/releases/tag/v1.14.7>, SHA-256
`72176dcf191cdbf5a5ea8e99ecc1cb2017fbaf842386ab2ae1436b5537d9a852`).
Из проекта собирается APK **AURA-native v0.10-1** (`app.homemusic`, versionCode 7502, versionName `v0.10-1`),
который подписывается тем же ключом, что и AURA v0.75-1, и ставится поверх неё как обновление.

Изменения относительно оригинала: только версия и название приложения (`AURA`). Сетевая логика, авторизация
(Хаб, Navidrome/Subsonic, Google-вход), «Моя волна», загрузки, LAN-воспроизведение и обновления
сохранены как в исходном APK.

## Что внутри

| Путь | Что это |
|---|---|
| `app/src/main/java` | Java-исходники, полученные декомпиляцией (jadx 1.5.1, CFR 0.152), которые компилируются, бинарно совместимы с остальным кодом и прошли сверку с оригинальным байткодом |
| `app/src/main/smali` | Классы, которые не удалось честно перевести в Java (в основном библиотеки: Compose, Media3, coroutines и т. п.). Собираются в dex тем же ассемблером smali, что использует Apktool |
| `app/src/main/res`, `assets`, `jniLibs`, `resources` | Ресурсы, ассеты, нативные библиотеки (FFmpeg) и Java-ресурсы из APK |
| `app/stable-ids.txt` | ID всех 7549 ресурсов оригинала: R8 вписал их в код числами, поэтому они обязаны совпадать |
| `auratools` | Шаги сборки (запускаются через JavaExec): smali → dex, API-jar для javac, вставка dex в APK |
| `SOURCES.tsv` | Какой декомпилятор дал каждый Java-файл |
| `tools/decompile` | Скрипты, которыми получен проект (повторяемо) |

Счётчики (из 7195 классов оригинального `classes.dex`):

* 4653 класса собираются из Java-исходников (4641 файл: jadx 4321, CFR 266, jadx + автоправки 54);
* 2542 класса собираются из smali;
* из 221 файла собственных классов приложения (`com.eddyizm.tempus.*`, включая `homemusic.*`) в Java 144.

## Почему не «просто взять исходники Tempus»

* Упаковщика/протектора нет: в APK один обычный `classes.dex`, Application — `com.eddyizm.tempus.App`.
* Обфускация — R8 в режиме `-repackageclasses`: 6184 класса (код приложения **вместе с библиотеками**)
  переименованы в короткие имена и перенесены в корневой пакет. Здесь он называется `defpackage`, потому что
  в Java нельзя импортировать класс из безымянного пакета. Имена `com.eddyizm.tempus.*` сохранились только
  у 227 классов, на которые ссылаются манифест, разметка и Gson. R8 также сливал классы приложения и библиотек
  (например, утилиты Preferences из Tempus и код HomeMusic лежат в общих классах).
* База — Tempus **v4.29.0**: совпадают версии всех зависимостей, схема БД (версия 23) и набор классов.
  Пакет `lan.*` уже есть в Tempus (с 4.28), так что это не код HomeMusic.
* Kotlin-исходники Tempus ссылаются на настоящие имена библиотек, а в этой сборке библиотеки переименованы
  и частично встроены в код приложения. Поэтому исходники Tempus используются как справочник,
  а собирается именно декомпилированный код: только так он связывается с остальным байткодом без потерь.

## Как получены исходники

1. `apktool d` → ресурсы и smali; корневой пакет переименован в `defpackage` (`tools/decompile/repackage.py`).
2. R8 удалял «пробрасывающие» конструкторы (объект создаётся сразу вызовом конструктора родителя). В Java так нельзя,
   поэтому `ctorfix.py` добавляет такие конструкторы явно (809 шт., поведение идентично).
3. Каждый класс декомпилирован тремя способами: jadx, jadx с механическими правками (`jadxfix.py`) и CFR
   (по jar, полученному dex2jar).
4. `ensemble.py` для каждого файла выбирает первый вариант, который
   * компилируется (ECJ для быстрого поиска, затем javac, как в AGP);
   * бинарно совместим с оригиналом: те же суперкласс, интерфейсы, поля и методы (`Compat.java`);
   * не теряет обращений к методам, полям и строкам по сравнению с оригинальным байткодом (`Sem.java`);
   * не содержит маркеров «метод не декомпилирован».
   Если ни один вариант не прошёл, класс остаётся в smali.
5. `mkproject.py` раскладывает Java-файлы и оставшийся smali по проекту.

## Сборка

Нужны JDK 17+, Android SDK с platform 37 и Gradle 9.6 (есть wrapper).

```
./gradlew :app:auraReleaseApk
# → app/build/outputs/aura/AURA-native-release-unsigned.apk
zipalign -f -p 4 AURA-native-release-unsigned.apk aligned.apk
apksigner sign --ks aura-release.jks --out "AURA-native v0.10-1.apk" aligned.apk
```

В CI это делает `.github/workflows/aura-native-release.yml` на self-hosted Windows-раннере: подписывает
ключом из секретов `AURA_KEYSTORE_*` и проверяет, что сертификат совпадает с AURA v0.75-1.
